## Scope

This patch came from a bug hunt across both surfaces.

- [Limits #34](https://github.com/aklkbqx/agy-swap/issues/34): `limit set` and cooldown parsing reject durations above the 7-day ceiling in every syntax. Oversized values had overflowed into short or negative cooldowns (`9223372036854775807` became -1 minute, `213503982336d` became 33 hours).
- [Update #35](https://github.com/aklkbqx/agy-swap/issues/35): Homebrew updates are confirmed by the version the linked binary reports; a stale tap gets one `brew update` and a retry, and an unchanged install is an error instead of a success message.
- Site: the saved or system theme is applied before first paint, and the page follows OS theme changes until a choice is saved. Unknown addresses return a 404 page instead of the homepage, and `/install` opens the install page.

## Hunt coverage

- Static analysis with a broad golangci-lint profile: 350 findings triaged (nilerr, wastedassign, forcetypeassert, unused, gosec G115/G302/G402); none was a defect.
- Fuzzing of the input parsers: about 674,000 executions without a panic; a follow-up probe found the duration overflow.
- Code review: updater, backup encryption, display width and Thai text handling, account rotation. The rotation review found a `next` defect fixed in [v2.11.8](v2.11.8.md).
- Site: 3 viewports × 4 languages × 2 themes × 2 pages without overflow, failed requests, raw translation keys, broken anchors or console errors; theme toggle, OS selector, copy feedback and mobile menu checked; accessibility scan without confirmed violations. One suspected favicon defect was a false finding and was closed without a change.

## Candidate verification

Tests were written first and failed before each fix: duration overflow, four Homebrew cases with a stub `brew` that exits 0 like the real one, theme bootstrap executed against saved, OS, invalid and blocked-storage cases, the toggle following OS changes, and Nginx routing. `make release-check` passed: tests, race detector, vet, golangci-lint 0 issues, TUI smoke at four sizes, govulncheck without vulnerabilities, Site 80/80 tests and build, and a production-equivalent preview whose smoke test checks `/install` (200) and an unknown path (404).

- `make release-assets` ran from tag `v2.11.7`; every asset records `go1.27.2`, `github.com/aklkbqx/agy-swap/v2` and `v2.11.7`. GitHub asset digests match `checksums.txt`.
- Homebrew tap updated. Mac active path `/opt/homebrew/bin/agy-swap`: `agy-swap v2.11.7 (release-v2.11.7)`, SHA-256 equal to the darwin/arm64 asset.
- Public module proxy, isolated GOPATH, default `GOTOOLCHAIN=auto`: `@latest` resolves to v2.11.7 and `go install` builds `agy-swap v2.11.7 (dev)` with go1.27.2. The proxy served v2.11.6 for `@latest` for a few minutes after tagging until the version was requested explicitly.
- Site published. The first `site-verify-live` run failed only on the internal 404 page, which the new Nginx configuration correctly answers with 404; after PR #37 it compares `/install` and an unknown path with the built pages, and the run matched production (endpoints, installer redirects and versions, demo 404, every built file byte for byte). At 03:08Z the live site reported v2.11.7.
- The live site became unreachable at the hosting level from about 03:12Z, after the v2.11.7 verification; it was back by 04:55Z, by then serving v2.11.8. The v2.11.7 Site changes were checked again on the v2.11.8 deployment, which carries them unchanged (see [v2.11.8](v2.11.8.md)).

## Limits

- The Homebrew retry path runs when a v2.11.7 installation updates to a later release; the stale-tap case is covered by stub tests, not by a real stale tap.
- Windows was not run natively for this release.
