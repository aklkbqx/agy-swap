## Scope

- [Login #42](https://github.com/aklkbqx/agy-swap/issues/42): `agy` ran in its own background process group while it shared the terminal. Reading input or changing terminal settings stopped it with `SIGTTIN`/`SIGTTOU`, so `add` froze until the timeout. On macOS and Linux, when stdin is the controlling terminal and agy-swap owns it, `agy`'s group now owns the terminal while it runs, and agy-swap takes the terminal back as soon as `agy` exits, before the TUI returns to raw mode. Pipes, background runs and Windows are unchanged. Reported in [#41](https://github.com/aklkbqx/agy-swap/pull/41). That PR's handoff did not give the terminal back, which would have stopped agy-swap after every login from the TUI; the review there requested changes, and the PR's other parts remain with its author.
- Site: version alignment only.

## Candidate verification

A pseudo-terminal regression test starts a new session with the pseudo-terminal as its controlling terminal. It drives the real add flow with a fake credential store and a stand-in `agy` that changes terminal modes, then switches to raw mode as the TUI does. It fails on the v2.11.8 behavior (the child is stopped) and on a foreground-only handoff (the terminal stays with the child's group), and it passed 30 consecutive runs under the race detector. `make release-check` passed: tests, race detector, vet, golangci-lint 0 issues, TUI smoke at four sizes, govulncheck without vulnerabilities, Site 80/80 tests and build, production-equivalent preview. `go vet` is clean for linux and windows on amd64 and arm64.

## Limits

- No login was run with the real `agy` for this release: the add flow clears the active Antigravity credential, which on macOS lives in the system keychain. The terminal handoff is covered by the pseudo-terminal test; the first real check is the next account added from the TUI.
- Windows was not run natively; its code path is unchanged apart from a no-op.
